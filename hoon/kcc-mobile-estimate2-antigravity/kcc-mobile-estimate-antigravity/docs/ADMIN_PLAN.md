# KCC 홈씨씨 렌탈 신청 관리자 기획

작성 기준: 2026-11-11 / 화면 시안: `web/admin.html`

## 1. 목적과 범위

견적서에서 접수된 렌탈 신청을 고객별로 확인하고, 신분증·필수 동의·전자 서명을 검토한 뒤 보완 요청과 계약 진행 상태를 관리한다. 신청 접수와 계약 확정을 별도 상태로 관리한다.

동봉한 관리자 화면은 가상 데이터 6건으로 작동하는 UI 시안이다. 검색·상태 필터·상세·동의서 보기·처리 메모·검토 상태 변경을 체험할 수 있다. 실제 신청 데이터 연동, 로그인, 서류 원본 조회, 메시지 발송, 영구 저장은 구현되지 않았다. 시안에서 상태를 변경해도 새로고침하면 초기화된다.

## 2. 화면 구성

| 영역 | 구성 | 주요 동작 |
|---|---|---|
| 현황 카드 | 전체 신청 / 신규 접수 / 보완 필요 / 계약 확정 | 운영 API 집계. 필터 적용 범위와 기간을 명시 |
| 신청 목록 | 접수번호·일시 / 계약자 / 선택 렌탈·금액 / 제출 자료 / 진행 상태 / 담당자 | 이름·접수번호 검색, 상태 필터, 페이지 이동. 운영 확장: 기간·담당자·견적번호 검색 |
| 신청 상세 | 신청 당시 계약자·연락처·생년월일, 연결 견적, 초기·월·총 납부액 | 현재 견적과 신청 당시 확정 스냅샷 구분 |
| 서류 검토 | 신분증·서명 각 파일, 세부 확인 체크 | 권한 검사 후 원본 조회. 등록 완료와 본인 확인 완료를 구분 |
| 동의 내역 | 동의 항목별 여부·약관 버전·서버 접수 시각·원문 | 신청 당시 원문 고정 조회. 수정된 최신 약관으로 덮어쓰지 않음 |
| 처리 이력 | 상태 변경·열람·보완·담당자 변경·메모 | 누가, 언제, 무엇을 했는지 추가 기록. 기존 이력 수정 금지 |
| 운영 액션 | 담당자 지정 / 상태 변경 / 보완 요청 / 취소 | 사유 및 근거 입력, 서버의 상태 전이 검증, 중복 실행 방지 |

PC는 좌측 탐색 + 목록 + 우측 상세 패널로 구성한다. 모바일 관리 화면은 목록 요약 카드와 전체 화면 상세로 확장한다. 동봉 시안의 좁은 목록은 가로 스크롤 방식이다.

## 3. 상태와 전이

| 상태 코드 | 화면 명칭 | 진입 조건 / 가능한 다음 단계 |
|---|---|---|
| received | 신규 접수 | 서버에 신청·동의·서류·서명 저장 성공 후 부여 → review 또는 cancelled |
| review | 서류 확인 중 | 담당자 배정 후 검토 시작 → needs_info, screening 또는 cancelled |
| needs_info | 보완 요청 | 보완 항목·사유 필수. 고객 재제출 성공 → review |
| screening | 심사 중 | 필수 동의·신분증·서명 검토 완료 → confirmed, needs_info, rejected 또는 cancelled |
| confirmed | 계약 확정 | 렌탈사 승인과 계약 확정 증빙, 확정 일시·계약번호 기록. 화면 체크만으로 확정 불가 |
| rejected | 진행 불가 | 렌탈사 심사 결과와 안내 가능한 사유 기록 |
| cancelled | 취소 | 취소 주체·사유·시각 기록. 재신청은 새 접수로 연결 |

시안은 상태 선택 UI와 기초 확인만 구현했다. 운영에서는 위 상태 전이표를 서버에서 강제한다. 확정 이후 변경·정정은 별도 권한과 변경 이력이 필요하다.

## 4. 신분증·서명 검토 화면

1. 목록과 기본 상세에는 신분증 원본, 생년월일 전체, 전체 전화번호를 노출하지 않는다.
2. `원본 열람` 선택 → 필요 권한 검사 → 민감정보 열람용 재인증 → 열람 사유 입력 → 제한된 시간 동안 표시.
3. 원본은 비공개 저장소에서 짧은 만료 시간의 접근으로 전달한다. CDN 공개 경로·메일 첨부·공유 링크에 원본을 두지 않는다.
4. 화면에 열람자·열람 시각·접수번호 워터마크. 축소·확대·회전·다음 서류 탐색 지원. 기본 다운로드 및 일괄 다운로드 버튼은 제공하지 않는다.
5. 조회 성공·실패·다운로드 예외·권한 변경을 서버 감사 로그에 기록한다. 화면 워터마크는 접근 제어의 대체 수단이 아니다.
6. ID 이미지의 불필요한 고유식별정보는 확정된 수집 정책에 맞춰 마스킹한다. 주민등록번호 뒷자리까지 반드시 수집한다고 가정하지 않는다. 렌탈사 필수 항목, 수집 근거 및 보관 정책 확정 뒤 필요한 부분만 처리한다.
7. 신분증 등록이나 서명 이미지 존재만으로 휴대폰 본인 인증, 전자서명 서비스 인증, 신용조회 권한이 확보된 것으로 표시하지 않는다.

## 5. 권한

| 역할 | 신청 목록·기본정보 | 신분증·서명 원본 | 상태·메모 | 계정·권한·감사 |
|---|---|---|---|---|
| 상담 담당자 | 배정 건, 마스킹 기본값 | 기본 불가 | 배정 건 상담 메모, 보완 요청 권한을 별도 부여 | 불가 |
| 심사·계약 담당자 | 권한 범위 내 건 | 별도 권한 + 재인증 | 서류 확인·심사 결과 반영 | 자신의 열람 이력 |
| 운영 관리자 | 허용 조직·사업 범위 | 별도 민감정보 권한. 관리자라는 이유만으로 자동 부여하지 않음 | 담당자 배정·상태 정정 | 운영 범위 감사 조회 |
| 보안 관리자 | 업무 데이터 최소 접근 | 기본 불가 | 기본 불가 | 계정·권한·감사·보존 및 파기 정책 |

권한은 UI 버튼 숨김과 별개로 모든 조회·파일 접근·수정 API에서 검사한다. 소속 조직과 배정 범위를 요청마다 검증한다.

## 6. 보완 요청

- 보완 유형: 흐린 신분증 / 신분증 일부 잘림 / 계약자 정보 불일치 / 서명 확인 필요 / 기타.
- 담당자는 확인한 근거와 고객에게 전달할 문구를 분리 입력한다.
- 발송 전 수신자와 메시지 미리보기. 내부 메모가 자동 발송되지 않게 분리한다.
- 고객 링크는 만료 가능한 일회성 인증 경로. 접수번호만으로 열람·파일 교체를 허용하지 않는다.
- 재제출 시 서류 버전과 제출 시각을 기록하고 `서류 확인 중`으로 이동한다. 이전 자료 보존/폐기는 확정 정책에 따른다.
- 핵심 계약 내용이나 동의 항목이 바뀌면 재동의·재서명을 받는다.
- 동봉 시안은 메시지를 발송하지 않으며 화면에 이 사실을 명시한다.

## 7. 운영에서 결정할 항목

렌탈사 및 처리 주체 명칭, 확정 동의서 3종, 개인정보 항목·보존/파기 기간, 본인 확인 방식, 신분증 마스킹 기준, 계약 확정 권한·근거, 담당자 범위, 보완 연락 채널, 접수 확인 알림과 업무시간, 보안·감사 책임자를 운영 설정으로 확정한다. 시간·법적 효력·승인률을 임의로 약속하는 문구는 넣지 않는다.

## 8. 출시 수용 기준

- 다른 담당자·조직의 신청 ID를 직접 요청해도 권한 없이 조회/수정할 수 없음.
- 로그인하지 않으면 목록·서류 API 401. 권한 부족은 403. `admin.html` 주소를 숨기는 방식으로 보호하지 않음.
- 원본 파일 주소 유출 시 만료·권한 검사로 재접근 차단. 응답 Cache-Control: no-store.
- 검색·통계·목록·로그에 생년월일 전체, 신분증 내용, 서명 원본을 불필요하게 포함하지 않음.
- 계약 확정은 동의 확인 체크만으로 완료되지 않으며 실제 계약 근거가 필요함.
- 파일 열람과 상태 변경 감사 로그가 신청 기록과 일관되게 연결됨.
- 민감 파일을 포함한 백업·재처리 큐·임시 파일도 동일한 보존 정책 적용.
