# 안티그래비티 작업 지시

첨부한 KCC 홈씨씨 견적서 패키지를 현재 운영하는 모바일 견적서 프로젝트에 통합해줘. 기존 디자인·가격 비교·제품 사양·상담 흐름을 유지하면서 렌탈 신청 기능과 관리자 운영 기능을 완성해줘.

먼저 README.md → DEVELOPMENT_NOTES.md → docs/ADMIN_PLAN.md → docs/API_CONTRACT.md → docs/QA.md 순서로 읽고 현재 저장소의 프레임워크, 견적 데이터, 인증, CRM, 배포 구성을 확인해. 기존 프로젝트가 React/Next 등이라면 같은 디자인과 동작을 컴포넌트로 옮겨. 이 패키지는 실행 가능한 프런트 시안이고 실제 접수 서버는 아직 연결되지 않았어.

## 고객 화면

- 렌탈 카드 선택 시 해당 카드 아래 상담하기 / 렌탈 신청하기 두 버튼. 신청 버튼은 큰 면적의 오렌지 강조.
- 모바일 전체 화면 신청 모달, PC 중앙 모달. 상단 진행 단계와 하단 다음/이전 고정.
- 1단계: 인증된 견적에서 계약자 정보 읽기. 생년월일 YYYY-MM-DD 자동 하이픈. 월·초기·총액은 서버 견적 버전에 결합. 금액 확인 체크.
- 2단계: 계약자 신분증 1장 사진 선택 또는 촬영. 미리보기, 교체, 삭제, 파일 오류. HEIC 서버 검증·변환.
- 3단계: 승인 약관 3종의 전체/개별 동의. 초기 미동의. 약관 원문 보기. 실제 손서명. 핵심 신청 내용 변경 시 재서명.
- 최종 접수는 서버에 신청과 파일·동의·서명 저장이 모두 성공한 경우에만 완료 처리. 새로고침·중복 클릭·네트워크 재시도에서도 중복 접수 금지.
- 결과는 '렌탈 신청 접수 완료'. 렌탈사 승인·계약 확정과 구분.

## 서버·관리자

- 기존 견적 접근 권한과 실제 고객 데이터를 연결하고 이름/휴대폰 쿼리 값을 인증으로 신뢰하지 마.
- API_CONTRACT.md 기준으로 세션, CSRF, 서버 검증, 비공개 저장소, 동의/견적 스냅샷, 서명 증빙 결합, 접수번호, Idempotency와 활성 신청 중복 방지를 구현해.
- 관리자 시안의 가상 데이터를 실제 권한 범위 API로 대체해. 관리자 로그인, 역할/배정 범위, 원본 열람 재인증·사유·접근 로그, 상태 전이, 메모 이력, 보완 요청을 구현해.
- 관리자 권한을 주소 숨김이나 프런트 변수로 구현하지 마. ID·서명을 public 폴더, 공개 URL, 브라우저 저장소, 분석 이벤트, 메일 첨부에 저장하지 마.
- 계약 확정은 실제 승인/계약번호 등 근거가 있어야 해. 체크박스 3개로 계약을 확정하지 마.
- 운영 DB와 메시지 발송은 개발/테스트 환경 검증 후 연결해. 실고객 정보 대신 테스트 자료를 사용해.

## 구현 완료 기준

1. 기존 견적 항목·가격·상담 기능 회귀 없음.
2. iOS Safari / Android Chrome에서 촬영·사진 선택·키보드·손서명·하단 버튼 정상.
3. 입력 누락·잘못된 생일·파일 오류·동의 누락·빈 서명 차단.
4. 서버 실패 시 접수 완료 표시 없음. 중복 재시도는 동일 접수번호.
5. 고객은 다른 고객 자료에, 담당자는 권한 밖 신청/원본에 접근할 수 없음.
6. 신청 당시 견적·약관·서명이 연결되어 관리자에서 확인 가능.
7. 보완/취소 사유, 열람/수정 감사 이력, 파일 보존/파기 정책 반영.
8. 운영 약관·처리 주체·수집 항목·보관 정책·본인 확인 기준을 승인 값으로 교체하고 체험 문구는 실제 기능 완성 후 제거.

변경 파일, DB/API 설정, 배포 환경변수 이름(비밀 값 제외), 테스트 결과, 남은 연결 항목을 정리해줘. API나 외부 시스템이 없는 상태를 완료로 보고하지 마.
