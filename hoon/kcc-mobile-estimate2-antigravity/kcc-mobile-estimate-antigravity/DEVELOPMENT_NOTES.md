# 개발 인계 메모

## 파일 구조와 통합 지점

빌드 없는 HTML/CSS/JS이다. 기존 견적서 스크립트 `app.js` 다음에 신청 기능을 로드한다. 순서는 rental-config.js → app.js → rental.js. 상담 버튼은 기존 openConsult 함수를 재사용한다. 각 렌탈 버튼은 data-plan, data-plan-actions, data-rental-open, data-rental-consult의 동일 plan key로 연결된다. 결제 카드 내부에 버튼을 중첩하지 않고 형제 영역에 CTA를 배치했다.

기존 견적서는 원본 URL의 정보에 기초한 별도 디자인 시안이다. 이번 패키지를 만드는 과정에서 원본 kcc-estimate2.vercel.app의 운영 저장소나 배포는 수정하지 않았다. 새 시안은 원본 프로젝트에 통합하기 위한 자료다.

## 신청 동작

- customerName, phone은 demo 설정에서 읽기 전용으로 표시. 데모 번호는 마스킹되어 있어 live 전송 가드에서 차단된다.
- 운영에서는 서버가 허용한 견적 컨텍스트로 데이터를 주입한다. 인증 없이 전체 개인정보를 정적 소스에 넣지 않는다.
- 사진은 브라우저 메모리의 File과 Object URL로만 미리보기한다. 교체·삭제·종료·완료 시 URL 해제. localStorage와 sessionStorage를 사용하지 않는다.
- `capture=environment`는 촬영 의도 힌트이며 브라우저가 실제 카메라 UI를 보장하는 API는 아니다.
- 파일 헤더의 JPEG/PNG/HEIC 여부와 10MiB 제한은 UX 검증. 실제 운영 검증·변환·악성 검사·마스킹은 서버 책임이다.
- 포인터 이벤트로 서명을 그리며 입력 내용·동의·사진 변경 시 기존 서명을 비운다. 동의 변경 후 재서명을 받아 제출 내용과 일치시킨다.
- 다른 렌탈로 새 신청을 열면 모든 입력·동의·사진·서명이 초기화된다. 뒤로 가기는 현재 입력을 유지한다.
- termsVersion과 각 동의 항목은 별도 설정. 본문은 문구 확정 전 예시이며 승인된 것으로 취급하지 않는다.
- 제출 어댑터는 동일 출처 multipart POST, CSRF 토큰, 쿠키 인증, Idempotency-Key, 타임아웃, 정상 접수 응답 검증을 포함한다. 서버 구현과 통합 검증 전에는 demo를 유지한다.

## 관리자 시안

admin.js의 samples는 가상 자료다. 고객 입력을 관리자에게 보내거나 저장하지 않는다. 문서 뷰어에는 실제 ID나 서명 이미지 대신 명확한 SAMPLE 표시 영역을 사용했다. 검색·필터·검토 플래그·상태·메모는 해당 페이지 메모리 안에서만 동작한다.

## 실제 운영 전 필요한 연결

고객 인증/견적 조회 API, 접수 DB, 비공개 파일 저장소, 서버 파일 검사/변환, 승인 동의서, 관리자 인증/권한, 감사 로그, 실제 계약 상태 연결, 보완 알림 채널. API와 운영 규칙의 상세는 docs 디렉터리에 있다.

## 브랜딩 및 외부 리소스

기존 디자인의 KCC 로고, 오렌지 CTA, 네이비 금액 카드, 연한 블루 동의 영역을 이어간다. 공간 이미지는 제품/시공 실적 증빙이 아닌 연출 이미지다. ASSET_SOURCES.md를 확인하고 고객 공개용 자료는 사용 권한이 있는 이미지로 교체한다. Google Fonts가 차단되어도 시스템 글꼴로 작동한다.

## 배포

web 폴더는 정적 시안이다. Vercel/Netlify 등에 정적 배포할 수 있으나, 정적 호스팅만으로 운영 접수 기능은 동작하지 않는다. 원본 프로젝트에 API 및 인증이 있다면 기존 구조를 우선 사용한다. 이 ZIP에는 Site 프로젝트 ID, Git 인증 정보, 비밀 키, 고객 원본 신분증·서명이 포함되어 있지 않다.
